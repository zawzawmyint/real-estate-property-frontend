# Architecture

`src/app/(public)` and `src/app/(staff)/crm` own route layouts, using shared layout components and semantic tokens. The public routes implement property search, featured content, listings, detail/gallery, Contact, Agents and agent profiles; CRM implements property inventory and lifecycle forms. Property presentation lives in `src/features/properties`; public agency reads and presentation live in `src/features/agency`, while the property-independent enquiry form remains a Leads feature. Error/loading/not-found UI distinguishes missing public listings from unavailable API service responses.

`src/components/ui/button.tsx` is a locally owned shadcn-style Base UI primitive, using `@base-ui/react/button`, class-variance-authority and token styles. `src/components/ui/input.tsx`, `field.tsx`, `alert.tsx`, `card.tsx` and `empty.tsx` are locally owned Base Nova-derived primitives. The login page composes `Card`/`CardContent`; `src/components/layout/empty-state.tsx` composes the Empty exports for the homepage and CRM placeholders. The login form uses field errors for validation and alerts for persistent sign-in feedback. `components.json` declares the Base Nova registry style; no Radix runtime is installed. Reuse the local catalog first, then add only an appropriate official Base Nova registry component when a standard primitive is missing, adapting it to the semantic palette. Native links retain link semantics.

Server Components call `src/lib/api/server.ts`, protected by `server-only`. It reads validated `API_URL` and calls the transport. Browser requests use `/api/v1/*`; Next rewrites to Express. Rewrites use the configured origin at build/dev startup; rebuild after changing it for production. Do not put the backend origin in NEXT_PUBLIC variables.

CRM uses a server-only, no-store session lookup during dynamic rendering and repeats the check at protected page/data entry points. A Next.js Proxy makes an optimistic `/crm/:path*` redirect when the configured session cookie is absent (`agency.session` outside production, `__Host-agency.session` in production); it performs no verification and never authorizes a request. The layout starts the server session lookup without awaiting it, keeps one persistent account provider above compact and expanded account views, and suspends only the account region. Properties and Leads render static headings and filter structures while role-sensitive controls and private results wait for verification. Properties fetches its inventory concurrently with session verification but emits records only when both succeed; Leads keeps provisional role-neutral filters inert until verified role parsing resolves. The transport forwards only the configured auth cookie to Express, narrows returned staff data before passing props, and distinguishes anonymous sessions from service failures. Browser sign-in, sign-out and interactive session state use the Better Auth React client through the same-origin proxy. Express remains the authorization boundary.

CRM list pages reuse an application-level presentation layer: PageHeader and FilterPanel in src/components/layout, DataTable<T> and CollectionPagination in src/components/crm, and TextField, SelectField and TextareaField in src/components/forms. These components own repeated layout, table, pagination and labelled-field structure; Properties and Leads retain their feature-specific columns, filters, URL behavior, validation, permissions and request coordination. DataTable has no client directive, so server-owned render functions stay within the server graph; client features may use their own functions from their client graph. Shared CRM components do not fetch, authorize or import feature/API modules.

Public pages use PublicSectionHeader and PublicSearchPanel in src/components/layout and PropertyGrid in src/features/properties/public. The homepage owns its hero panel around PropertyFilters home; PropertyFilters owns its desktop listing panel and mobile Sheet. PropertyGrid reuses the existing PropertyCard with optional resultsQuery for return links. Public search and PropertyInquiryCard use the same TextField/SelectField/TextareaField as CRM, preserving registration refs and help/error descriptions. Headings/panels/grids stay server-compatible; domain fetching, exact AED validation, navigation, mobile state and inquiry receipts remain feature-owned. Distinct hero/gallery headings, purpose radios and inline sort controls remain local. See [shared public component specification](../specs/shared-public-components/spec.md).

Express owns business rules, data access, authorization and media. This repo does not import Prisma. The backend OpenAPI contract includes property and lead APIs; committed frontend snapshots are `docs/contracts/properties.openapi.yaml` and `docs/contracts/leads.openapi.yaml`, and `openapi-typescript` generates their corresponding types. Browser reconciliation reads use the same-origin `/api/v1` proxy; Server Components use the server-only transport. Property writes move from client UI through feature-owned Server Actions and server-only mutation transport to Express.

The property feature is organized by responsibility: `data/` holds inputs, filters, generated aliases/result types, request/error handling, browser reads, server-only writes and Server Actions; `public/` holds listing, filter, pagination and gallery UI; `crm/` holds inventory, form, lifecycle, photo and read-only UI; `shared/` holds only reused presentation/loading modules. Imports name concrete modules; there are no feature barrels or compatibility forwarders. The action boundary verifies a live staff session and role, parses untrusted IDs/payloads/files, validates the request `Origin`, and forwards only the configured staff-session cookie plus that Origin. It returns a serializable success/error union; Express independently validates and authorizes every operation. Property reads retain `no-store`; confirmed client results update local state and explicitly refresh dependent server content.

`PropertyImage` is shared across public homepage, card and gallery presentation; CRM continues to use its existing local image markup. `property-loading.tsx` exports both public-card and CRM-inventory fallbacks. CRM inventory parses the URL and renders its heading and filters before an async `PropertyInventoryResults` component fetches rows inside a query-keyed Suspense boundary. Its title and View details links target the authenticated read-only `/crm/properties/[id]` page for every staff role; the `PropertyReadOnly` presentation displays the Agent notice and omits owner contacts for Agents, while Admin/Manager can navigate to `/edit`. Agent `/edit` requests redirect to canonical details. Public `/properties/[id]` navigation is separately labelled and rendered only for published, available listings. `PropertyFormSection` is a client-neutral card wrapper shared by editable form fields, the form's photo section and the read-only presentation, so the detail route does not import client form-field code solely for its layout. `useClientReady` keeps pre-hydration controls inert. Shared create/edit fields, read-only presentation, sidebar lifecycle controls and `SubmitButton` prevent form ownership from being duplicated. The native Better Auth client contract remains unchanged.

Lead UI and data live in `src/features/leads`: public inquiry uses an authenticated server relay, while CRM reads and mutations retain the existing server-only/session-checked boundaries. Create feature-owned components, API adapters and schemas under `src/features/<feature-name>` when needed. Share primitives only for actual reuse. The staff login uses React Hook Form 7.90.0 with `@hookform/resolvers` 6.0.0 and Zod 4.6.7: the form library owns client field state and validation, the native `FormData` is synchronized before resolver validation for password-manager autofill, and Express remains authoritative. `src/lib/auth/roles.ts` owns the frontend tuple, type and guard for the existing staff-role contract; the transport, Better Auth client typing, role labels and browser coverage derive from it. Better Auth 1.7.12 is installed for staff authentication; defer global state, drag/drop and localization libraries until their features require them. Storage adapters live in the backend.

## Shared-code ownership

The shared route loading presentation is exported directly from `src/components/ui/loading-state.tsx`. Its decorative skyline remains `BuildingLoader` in `src/components/ui/building-loader.tsx`. Property enquiries use `PropertyInquiryCard` in `src/features/leads/public/property-inquiry-card.tsx`; general agency enquiries retain `AgencyInquiryCard`. See the verified [naming maintenance specification](../specs/shared-code-naming/spec.md).
